## When this applies

Use `401-cleanup` when code has already changed and needs a focused cleanup pass. Each run targets either source or tests, never both.

If a test is failing and you don't know whether the fix belongs in the test or the product, use `402-test-correction` instead.

## Two target paths

- **Source cleanup**: remove duplication, clarify naming, reduce complexity. Does not touch tests.
- **Test cleanup**: reduce redundancy, improve readability, fix broken assertions. Adds no coverage, scenarios, or test files.

## What to watch for

- Choose one target type per run.
- Keep the cleanup boundary explicit.
- Treat broader refactors as a separate decision.
