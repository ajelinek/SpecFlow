## Sequence

1. `201-high-level-design`
2. `202-spec-design`
3. `301-spec-implementation`
4. Optional `401-cleanup`, once for source and once for tests

## Example prompt sequence

<PromptBlock title="Prompt sequence" text={`Run 201-high-level-design for invoice approval.
Use 202-spec-design for invoice approval with balanced coverage.
Run 301-spec-implementation for the invoice approval feature.`} />

If the feature is already in D10, `201` should reuse that feature's `F-ID` so the artifacts land in a folder like `.specflow/features/F003-invoice-approval/`.

## Why this is the default

- The project exists, so you can usually skip straight to `201`.
- The feature still deserves a short design and behavior spec.
- `301` already reviews and refines its own diff, so `401` is optional here.

<Callout tone="core" title="Good fit">
  Use this pattern when the domain and product shape are already clear enough that you do not need broad project-definition work.
</Callout>
