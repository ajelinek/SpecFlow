Bonus skills support the workflow. They are useful because they reduce uncertainty, not because they belong in every feature sequence.

## Typical uses

- `context-manager` when a repo needs fresh root `CLAUDE.md` guidance, plus nested overlays only where a subtree genuinely differs
- `gap-check` from inside another skill's input-validation step, when its Required Inputs need resolving before that step can proceed

`gap-check` is never typed directly — the 100-series skills call it by name, so it is a dependency of planning rather than a side skill you reach for yourself.
