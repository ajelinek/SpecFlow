The `100` series builds the shared context that makes feature design and implementation more predictable. Each skill produces a document that downstream workflows read instead of rediscovering the same context.

<Callout tone="tip" title="Not just for greenfield projects">
  Use it on existing projects too, when the domain, architecture, UX, or feature map is still implicit.
</Callout>

## The documents it produces

| Skill | Output path | What it captures |
|---|---|---|
| `100-domain-knowledge` | `.specflow/context/domain-knowledge.md` | Market, users, terminology, constraints, differentiators |
| `101-project-overview` | `.specflow/docs/D01-project-overview.md` | Product definition, user goals, success metrics |
| `102-system-architecture` | `.specflow/docs/D02-system-architecture.md` | Stack, components, deployment, testing strategy |
| `103-common-data-model` | `.specflow/docs/D03-common-data-model.dbml` (relational), `.specflow/docs/D03-common-data-model.md` (non-relational) | Data structures, relationships, business rules |
| `104-backend-architecture` | `.specflow/docs/D04-backend-architecture.md` | API design, service layering, auth, security |
| `105-frontend-architecture` | `.specflow/docs/D05-frontend-architecture.md` | Component structure, state, routing, styling |
| `106-ui-design` | `.specflow/docs/D06-ui-design.md` | Visual direction, color, typography, component appearance |
| `107-ui-experience` | `.specflow/docs/D07-ui-experience.md` | User paths, navigation, interaction/recovery, pages and routes |
| `108-ui-page-design` | `.specflow/docs/D08-ui-pages/<name>/` and `D08-ui-pages/index.html` | Stateful HTML previews, concise page notes, and a maintained route catalog |
| `110-feature-overview` | `.specflow/docs/D10-feature-overview.md` | Capabilities and thin vertical feature slices |

## Recommended sequence

Use this as a starting sequence, not a prerequisite chain. Run only what is missing or stale.

```
100 → 101 → 102 → 103 → 104 → 105 → 106 → 107 → [108 per page] → 110
```

Use available project evidence regardless of document order. `106` and `107` are independently optional and can run in either order: `106` sets visual presentation; `107` defines navigation and interaction behavior. `108` applies those decisions to individual pages.

<Callout tone="tip" title="103 follows the storage model">
  Relational design lives in one project-wide DBML file, including rule notes and open questions. Non-relational modeling uses Markdown. Mixed projects use both without duplicating definitions.
</Callout>
