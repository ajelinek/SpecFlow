Three skills sit outside the main SpecFlow lifecycle but support it directly. `context-manager` can be used at any point in a project. `gap-check` and `engineering-principles` are different — they are not meant to be invoked directly; they only run when another skill or agent loads them by name.

## The bonus skills

| Skill | What it does |
|---|---|
| `context-manager` | Creates or refreshes `CLAUDE.md` guidance so Claude Code can navigate the repo accurately |
| `gap-check` | Resolves a workflow's declared Required Inputs from existing context first, then asks about only what's left, one question at a time with a recommended answer |
| `engineering-principles` | Defines the shared engineering principles every design, build, and cleanup pass follows, led by reuse over creation |

<Callout tone="bonus" title="Bonus does not mean optional">
  `context-manager` sits outside the feature loop but can become important early when a repo needs trustworthy `CLAUDE.md` guidance for the first time.
</Callout>

<Callout tone="tip" title="gap-check is invoked by name, not typed directly">
  Most of SpecFlow's 100-series skills call `gap-check` from their own "Validate inputs" step instead of re-implementing their own ask-the-user logic. You will rarely, if ever, invoke it yourself.
</Callout>

## Skills in this section
