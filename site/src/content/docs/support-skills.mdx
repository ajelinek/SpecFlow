Three skills sit outside the main SpecFlow lifecycle but support it directly. `context-manager` and `deep-research` can be used at any point in a project. `gap-check` is different — it has model invocation disabled and is never typed directly; it only runs when another skill's step calls it by name.

## The support skills

| Skill | What it does |
|---|---|
| `context-manager` | Creates or refreshes `CLAUDE.md` guidance so Claude Code can navigate the repo accurately |
| `deep-research` | Performs multi-source live web research when current external information materially affects a decision |
| `gap-check` | Resolves a workflow's declared Required Inputs from existing context first, then asks about only what's left, one question at a time with a recommended answer |

<Callout tone="bonus" title="Bonus does not mean optional">
  `deep-research` is listed as a bonus skill, but `100-domain-knowledge` normally relies on it for live research. `context-manager` sits outside the feature loop but can become important early when a repo needs trustworthy `CLAUDE.md` guidance for the first time.
</Callout>

<Callout tone="tip" title="gap-check is invoked by name, not typed directly">
  Most of SpecFlow's 100-series skills call `gap-check` from their own "Validate inputs" step instead of re-implementing their own ask-the-user logic. You will rarely, if ever, invoke it yourself.
</Callout>
