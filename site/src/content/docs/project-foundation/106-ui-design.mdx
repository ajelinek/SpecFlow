## What this skill is for

`106-ui-design` records what the product should look and feel like. It produces a short visual decision sheet covering tone, color roles, typography, spacing, component appearance, and motion. Choices should be specific enough to apply consistently, without specifying every component.

`106` owns visual presentation. `107` owns navigation, page inventory, and interaction behavior. D05 owns implementation conventions and token organization; D06 can name visual values or reference an existing system without reproducing its definitions. `108` applies the direction to a particular page.

**Output path**: `.specflow/docs/D06-ui-design.md`

## When to use it

- When the project needs an agreed visual direction
- When the team needs to agree on brand direction, color philosophy, and typographic hierarchy
- When a rebrand or visual refresh changes the existing direction
- On existing projects where design decisions have accumulated without an explicit rationale

## When NOT to use it

- When existing brand and design-system guidance already answers the relevant questions
- For a small visual change that fits established conventions
- When `108-ui-page-design` would be sufficient without a broader design strategy

<Callout tone="optional" title="Independent of UX and navigation">
  `106` and `107` are independently optional and can run in either order. Use existing context when it already settles the decisions. Missing upstream documents are not a reason to generate the whole planning series.
</Callout>

## What it produces

- `.specflow/docs/D06-ui-design.md` with applicable decisions:
  - Visual Direction — tone, audience fit, and brand/design-system references
  - Color & Typography — semantic usage, themes, typefaces, and hierarchy
  - Layout & Component Appearance — density, spacing, hierarchy, and visual states
  - Motion & Visual Accessibility — motion treatment, relevant visual decisions, and pending checks
  - Alternatives Considered and Open Questions only when meaningful

The template uses short prompts, not a preselected palette, type scale, layout, or device priority. Omit unused sections and reference existing guidance instead of repeating it.

## Required inputs

1. Audience and context — users, tasks, devices, and relevant accessibility needs
2. Visual intent — desired tone, brand assets, or an established system to preserve
3. Constraints — confirmed component library, theme support, and relevant technical limits

Read `.specflow/context/domain-knowledge.md` when available before asking about gaps. Use its user needs, usage conditions, expectations, differentiation, and constraints to focus the visual direction. Ask only about remaining blocking gaps; uncertain or outdated research is not a confirmed requirement. Competitors and inspiration references are optional.

## What usually comes next

Use `107-ui-experience` if navigation and interaction decisions remain open, `108-ui-page-design` for a page that needs detailed design, or move directly to feature work. None is an automatic follow-up.

## Practical guidance

- Compare alternatives only for meaningful unresolved choices. There is no fixed direction count or required worker call; `@designer` can help with a focused visual brief when useful.
- The color system should define semantic roles (primary action, destructive, surface, border) not just color values. Usage rules matter as much as the colors themselves.
- Ground the core design focus in relevant domain findings and reference them briefly in Visual Direction, without copying the research. Respect confirmed D01 goals, brand guidance, and D05 constraints; research informs those decisions without overriding them.
- Every design decision should be traceable to a business goal, user need, or design principle. Avoid aesthetic choices that cannot be explained in those terms.
- Surface conflicts before changing established decisions. Label proposals and unverified values rather than presenting them as confirmed or accessible by default.

## Common mistakes

- Producing a color palette without semantic rules for how each color should be used
- Treating typography as a font choice rather than a hierarchy and scale
- Inventing additional themes, breakpoints, or component rules just to fill the template
- Making design decisions that contradict the component library already committed to in D05
