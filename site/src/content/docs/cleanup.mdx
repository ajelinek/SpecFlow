The `400` series covers two kinds of follow-up work:

- `401-cleanup`: cleanup-only refinement on an already-changed scope
- `402-test-correction`: investigate a failing test and decide whether the fix belongs in the test, the source, or the intended behavior

## The 401 rule

**One target type per run: source code or test code, never both.**

This keeps each pass small, reviewable, and easy to roll back. For both, run `401` twice.

<Callout tone="core" title="Where 401 fits">
  The Comprehensive and Conservative paths end with a source `401` run and a test `401` run. On Minimal and Lean it is optional, since `301` already includes independent review and bounded refinement.
</Callout>

<Callout tone="tip" title="402 is the red-test path">
  Use `402-test-correction` when a failing test leaves you unsure whether the defect is in the test, the production code, or the intended behavior. It stops and asks when the failure is really a business-capability question.
</Callout>
