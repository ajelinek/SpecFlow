The `200` series turns a feature request into a set of reviewable, implementation-ready artifacts. Each skill in this series produces a document that guides and constrains the implementation run that follows.

## The two skills

| Skill | Output | Required |
|---|---|---|
| `201-high-level-design` | `overview.md` — scope, user journey, acceptance criteria | Core |
| `202-spec-design` | `specs.feature` — numbered Gherkin scenarios | Core |

<Callout tone="core" title="The minimum viable design loop">
  The core delivery path is `201 → 202 → 301`. These two design skills persist feature intent and behavior. `301` then builds and independently reviews a codebase-grounded implementation design in memory before coding.
</Callout>

## All outputs go to the same path

Every skill in the `200` series writes to `.specflow/features/<fid>-<feature-slug>/`. The files accumulate across the loop and `301` reads all of them before coding.

```
.specflow/
  features/
    F003-invoice-approval/
      overview.md          ← written by 201
      specs.feature        ← written by 202
```

## Skills in this series

- **[201 High-Level Design](./201-high-level-design/)** — define the feature in plain language
- **[202 Spec Design](./202-spec-design/)** — write the Gherkin behavior scenarios
